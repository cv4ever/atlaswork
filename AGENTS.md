# Workbench prototype

- Which file owns what: README.md, "Where to change the UI".
- Agent behaviour and agent UI decisions live in `docs/agents-design.md` as D-codes. When you change how agents work, update the matching D-code in the same change.
- UI work follows `docs/page-design.md`: the page and widget parts to reuse, tints by kind, and progressive disclosure everywhere (compact states show an icon or face with the words as tooltip; text and secondary actions appear on expand, hover or focus).
- Visual language (palette, type, shapes, motion, do's and don'ts) is `DESIGN.md`; product truth is `PRODUCT.md`. Both feed the impeccable skill. When a UI change alters the visual language, update `DESIGN.md` in the same change, then run `node scripts/check-design-sidecar.mjs --fix` to bring its sidecar, `.impeccable/design.json`, along (`pnpm run lint` fails until you do).
- The paid MVP launch plan (stack, launch steps, risks, open checks) lives in `docs/mvp-launch-plan.md`. Update its D-codes when a launch decision changes. The repo is public (AGPL-3.0): prices, provider accounts, emails, tax and backup operations go in the private `cv4ever/atlaswork-private` repo, never here.
- Browser checks: open each tab with `openCheckTab` from `scripts/check-tab.mjs` (managed Chromium, signed out, no stale service worker); the app does not load in the default WebKit tab. `?fresh` resets this device's workspace to the demo seed (`?fresh=new`: what a new person gets); `?today=YYYY-MM-DD` pins the day routines run for. Open the dev server URL with both to test routines from a known state. Reusable regressions (skin, Chats) and the speed-measurement rule: README, "Verification".
- Review: `CODING_STANDARDS.md`.
- Parallel sessions: each session works in its own worktree and branch, never in a checkout another session uses: `node scripts/worktree.mjs add <topic>` makes `../workbench-prototype-<topic>` with `.env.local` and packages and names a free port for its Vite (Carlos's dev server on 5191 serves the main checkout, so your work shows there once merged). Keep one worktree for the whole session: after each fast-forward push to `main`, rebase it onto `main` for the next task. When the session ends, stop its Vite and run `node scripts/worktree.mjs remove <topic>`.
- Ship to production only with `pnpm run release` (README, "Releasing"). Production is a closed beta: signed-out visitors to app.atlaswork.app get `src/Gate.tsx` (waitlist, invited sign-in), and `check:bundle` fails a build without it. Throwaway signed-in accounts for browser checks: `node dev/test-account.mjs` with `WORKBENCH_SUPABASE_SECRET_KEY` set from the Bitwarden key of that name (README, "Accounts and server storage").
